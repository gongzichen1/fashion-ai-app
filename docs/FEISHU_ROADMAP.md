## 1. 目标架构

飞书 H5 使用 React + Vite，移动端优先并适配桌面端。生产环境使用单一 HTTPS 业务域名：同一域名提供前端静态资源与 `/api/*`，服务端建立 Secure、HttpOnly、SameSite 会话。

数据流：

`飞书客户端 → requestAccess → POST /api/auth/feishu/login → 飞书服务端校验/换取用户身份 → 本地 users 映射 → 会话 Cookie → 鉴权业务 API → 正式数据库 + 私有对象存储 + AI provider`

JSSDK 流程：

`前端请求当前 URL 的 JSAPI 配置 → 后端使用服务端凭据生成/获取鉴权材料 → h5sdk.config → 能力检测 → chooseMedia/分享 → 失败时给出浏览器文件选择或明确提示`

飞书官方说明网页应用可运行于移动端和桌面端、支持免登和 H5 JSAPI；多数 JSAPI 要先鉴权，参见[网页应用概述](https://open.feishu.cn/document/client-docs/h5/introduction?lang=zh-CN)和[H5 JSAPI 总览](https://open.feishu.cn/document/client-docs/h5/)。

## 2. 阶段与停止条件

### 阶段 0：整理和可复现基线

- 收敛目录：保留 `src/frontend` 微信端，将 React 原型整理为 `src/feishu-web`；归档物不进入运行镜像。
- 用 Python 3.11 干净环境安装依赖并执行 pytest、格式、静态检查。
- 构建 React/Vite 和 Flask Docker 镜像，记录版本、命令和结果。
- 已确认当前 CloudBase `/` 与 `/api/health` 返回 200（约 0.06–0.10 秒）；继续补做长时间空闲后的冷启动、容器日志和依赖 readiness 探测。
- 使用一张授权测试图片完成真实 AI 端到端调用，记录 requestId、时延、错误和模型版本。

停止条件：健康检查、干净环境测试、容器构建或真实 AI 任一阻断未定位时，不进入生产发布。

### 阶段 1A：后端生产底座

- 建立 `users`、`analyses`、`recommendations`、`favorites`、`wardrobe_items`、`user_profiles`、`feedback`；业务表强制 `owner_user_id`。
- 采用正式数据库；本地 JSON 只用于明确的开发迁移工具，不作为生产回退。
- 对象存储默认私有；保存对象 key、内容类型、大小、owner、用途、到期时间和引用状态。
- 原始上传默认保留 30 天。删除分析时：无长期引用则删除对象；收藏/衣橱长期引用需要用户显式确认并更新引用。
- `POST /api/analyze` 强制认证，返回 `requestId` 和稳定错误码；生产禁用静默 demo 结果。
- 用户资源接口统一分页、所有权校验、幂等删除和脱敏日志。
- `/api/health` 拆分 liveness/readiness，展示数据库、对象存储和 AI 配置状态但不泄露密钥。

### 阶段 1B：飞书 H5 MVP

- React 页面：首页、媒体选择、分析中、结果、历史、收藏、衣橱、偏好、个人中心和错误页。
- 使用 `requestAccess` 获取授权信息；调用 `POST /api/auth/feishu/login`，并实现 `GET /api/me`、`POST /api/auth/logout`。
- 使用 [`chooseMedia`](https://open.feishu.cn/document/client-docs/gadget/-web-app-api/media/video/choosemedia?lang=zh-CN) 处理飞书内拍照/相册；桌面端和普通浏览器提供文件选择回退。
- JSSDK 未初始化、客户端版本不支持、用户拒绝、文件无效、网络中断和 AI 超时均显示可操作错误。
- 分享使用受保护的稳定结果路由，接收者仍须登录且通过服务端授权；一期不生成公开图片链接。
- 价格、商品链接为空时不渲染购买入口；推荐图片只能标注为搭配示意。
- Vite 构建产物与 API 采用同源部署；前端路由刷新由 Flask 或网关回退至 `index.html`，但 `/api/*` 和静态对象路由不被吞掉。

### 阶段 1C：双端验收和内部发布

- 飞书移动端：免登、拍照、相册、分析、收藏、删除、分享和注销/退出。
- 飞书桌面端：免登、文件选择、窗口缩放、路由刷新、分享和键盘可达性。
- 两个真实飞书测试账号交叉验证历史、收藏、衣橱、结果和图片均不可越权。
- 刷新页面、换设备、容器重启和多实例后数据仍存在。
- AI 未配置、超时、限流、返回非 JSON、非法图片和断网不会生成假成功。
- 微信小程序核心分析、结果、天气和本地历史流程完成回归，服务端改造未造成破坏。

发布门槛：P0 全部关闭；核心链路通过率至少 95%；无跨用户泄露；失败有 requestId 可追踪；回滚演练完成。

### 阶段 2：5–20 人内部试运行

- 指标：媒体选择成功率、分析成功率、P50/P95 时延、失败分类、收藏率、衣橱添加率、7 日重复使用率和单次 AI 成本。
- 运营只读视图使用脱敏汇总；多维表格只接收汇总指标或无敏感业务字段的工单，不保存用户原图和主数据。
- 完成隐私说明、用户协议、图片删除说明、模型供应商说明、投诉渠道和故障回滚方案。
- 每周根据真实失败样本调整拍摄引导、提示词和推荐结构；不得用用户图片再训练，除非另行取得明确授权。

### 阶段 3：增强能力

- 接入经过授权的商品目录后，才开放真实价格、商品链接和购买跳转。
- 评估多件衣橱组合、天气/日程推荐和飞书消息提醒；新增权限遵循最小授权。
- 虚拟试衣单独立项，需通过许可证、GPU 成本、时延、隐私和公平性技术闸门。
- 面向外部客户或应用市场前，新增租户隔离、计费、审核材料和商店应用发布流程。

## 3. API 与数据验收契约

一期至少提供：

| 接口 | 核心约束 |
| --- | --- |
| `POST /api/auth/feishu/login` | 只接收短期授权码；服务端交换并防重放；成功设置会话 Cookie，不把飞书 token 返回浏览器 |
| `GET /api/me` | 返回最小用户资料和环境能力，不泄露飞书敏感字段 |
| `POST /api/auth/logout` | 撤销本地会话，重复调用幂等 |
| `POST /api/analyze` | 必须登录；multipart 图片；绑定 owner；返回 requestId、明确状态和分析 ID |
| `GET /api/analyses` | 游标分页，只返回当前用户 |
| `GET/DELETE /api/analyses/:id` | 所有权校验；删除遵循对象引用和生命周期规则；重复删除幂等 |
| 收藏接口 | 以用户 + 分析/推荐对象建立唯一约束，重复收藏不产生重复行 |
| 衣橱接口 | 只有用户明确添加才创建；支持分页、编辑、删除和来源追踪 |
| `GET/PATCH /api/profile` | 保存风格偏好和可选身材资料；敏感字段最小化；身材资料是否参与 AI 必须对用户透明 |
| `POST /api/feedback` | 绑定用户和 requestId（可选），运营可读取脱敏内容 |
| `GET /api/health` | 区分 liveness/readiness 和依赖状态；不返回密钥、连接串或内部异常 |

服务端授权规则：任何资源查询、更新和删除都同时使用资源 ID 与当前 `owner_user_id`；禁止先按 ID 读出后再在应用层判断。对象存储 URL 不作为权限凭据。

## 6. 决策和风险

- 正式数据默认采用关系型数据库加对象存储，不继续使用 JSON 文件。
- 多维表格只做脱敏运营出口，不做用户图片和核心业务主存储。
- 原始图片默认 30 天；长期保留必须因收藏/衣橱用途得到用户显式操作。
- 飞书内使用 `requestAccess`；普通浏览器仅提供文件选择和明确环境提示，生产不设绕过身份的测试登录。
- 一期不含虚拟试衣和商品交易。

当前 CloudBase HTTP 入口已恢复快速响应，但线上 `/api/analyze` 对测试图片约 0.109 秒返回固定粉色裙子，说明真实 AI 链路仍未成立；最没有把握的是 provider 视觉兼容性和生产环境配置。当前最大的潜在遗漏是应用管理员和信息安全审批周期，它属于仓库外依赖，应在开发开始时并行发起，而不是等代码完成后再申请。
