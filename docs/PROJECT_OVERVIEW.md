# 智搭项目概况

> 基线日期：2026-07-14  
> 说明：本文区分“仓库中已有实现”“历史记录声称已验证”和“本轮可复现验证”。计划中的飞书能力不等同于已经上线。

## 1. 产品定位

智搭是一套以服装图片识别和文字搭配建议为核心的穿搭助手。当前保留微信小程序，并已在本轮把 React/Vite 原型整理为飞书 H5 MVP；服务端仍为两端共用的 Flask API。飞书代码、MySQL/PostgreSQL 数据层和 COS 适配代码已经具备，但真实飞书凭据、管理员发布、移动/桌面端真机、托管数据库和真实 COS 尚未验收，现阶段仍不能称为已上线平台。

一期产品闭环定义为：

1. 用户在飞书中免登进入应用；
2. 拍照、从相册选择或从桌面上传服装图片；
3. 服务端调用多模态模型识别服装，并生成搭配建议；
4. 用户可查看自己的历史、收藏和衣橱，维护偏好；
5. 数据按飞书用户隔离，用户能够删除自己的记录和图片。

虚拟试衣、真实商品价格、购买跳转、外部客户多租户和商业计费不属于一期范围。

## 2. 当前用户流程

### 微信小程序现有流程

`首页选择风格或进入相机 → 拍照/相册选择 → 上传到 /api/analyze → 展示识别和搭配结果 → 本地保存历史/收藏 → 个人中心查看`

天气入口会先请求微信定位权限，再由后端调用 Open-Meteo 获取天气并使用规则生成穿衣建议。

### 飞书本轮实现流程（尚未完成平台发布验收）

`飞书工作台 → requestAccess 免登 → 服务端建立同源会话 → chooseMedia/文件选择 → 鉴权分析 → 持久化至正式数据库和对象存储 → 用户级历史/收藏/衣橱`

飞书官方将网页应用定义为可在客户端内运行的 H5 应用，支持一端开发、移动端和桌面端运行、免登及客户端 JSAPI；新项目采用 H5 而不是飞书小程序，参见[网页应用概述](https://open.feishu.cn/document/client-docs/h5/introduction?lang=zh-CN)和[小程序概述（不推荐）](https://open.feishu.cn/document/develop-gadgets-%28not-recommended%29/basic-information/overview?lang=zh-CN)。

## 3. 当前技术架构

| 层级 | 当前实现 | 状态与边界 |
| --- | --- | --- |
| 微信端 | 原生微信小程序，WXML/WXSS/JavaScript | 页面和主要交互已实现；相机、定位、保存图片和分享仍依赖真机权限验收 |
| 飞书 H5 | `src/feishu-web`，React 18 + Vite + TypeScript | 已实现响应式页面、API 客户端、`requestAccess`/`requestAuthCode`、JSSDK 配置、`chooseMedia`、浏览器文件回退和分享调用；构建结果与真实飞书双端行为仍待最终验证 |
| API | Flask 3，共用分析、结果、历史、收藏、衣橱、偏好、反馈和身份 API | 已增加飞书 OAuth v2、微信 jscode2session、统一会话、用户归属、分页、幂等删除和 requestId；真实平台凭据、权限及生产安全配置待验收 |
| AI | OpenAI-compatible `chat/completions`，视觉识别和文字推荐 | 本轮代码已改为生产失败返回 503 和稳定错误码；固定样例只在显式 `AI_DEMO_MODE` 下启用。线上旧版本仍返回固定兜底，必须重新部署后复验 |
| 结构化存储 | SQLAlchemy + JSON payload 兼容层 | 支持 SQLite、MySQL、PostgreSQL；按 owner 建索引、飞书外部身份唯一，真实托管实例与备份恢复待验收 |
| 图片存储 | 对象存储接口 + local/COS adapter | 已按用户 key 保存、鉴权代理读取、记录 30 天到期时间，并提供删除和到期清理 CLI；真实 COS 权限与平台定时调度待验收 |
| 公共服装目录 | 独立 `catalog_items` + 私有 COS `catalog/` 前缀 | 已实现去重盘点、测试资产过滤、人工授权清单、审核状态、鉴权图片和推荐配图；12 个候选尚未完成授权，在线批准数为 0 |
| 天气 | 后端调用 Open-Meteo，服务端规则给出建议 | 有参数范围校验和 8 秒超时；依赖外网和定位授权 |
| 部署 | Flask Dockerfile + CloudBase 历史测试域名 | 仓库有容器文件；当前线上实例、环境变量和真实 AI 链路须重新验证 |

目标架构是在同一生产域名下提供 React 静态资源和 `/api/*`：浏览器只与同源 Flask 服务通信，后端负责飞书身份交换、业务授权、数据库、对象存储和 AI 调用。飞书应用密钥、模型密钥只进入服务端密钥管理或环境变量。

## 5. 部署现状

- 仓库中存在 `src/backend/Dockerfile`、启动脚本和 CloudBase 所需的容器入口。
- 本轮已重新探测测试域名 `https://zhida-api-264856-5-1259394189.sh.run.tcloudbase.com`：`/` 与 `/api/health` 均返回 200，响应约 0.06–0.10 秒；此前 12 秒超时属于瞬态，当前未复现。该结果只证明现有 Flask 容器可响应，不代表正式数据和飞书链路可用。
- 本轮将项目 `style-1.png` 上传到线上 `/api/analyze`，约 0.109 秒即返回固定粉色裙子结果，确认线上当前仍在静默使用演示兜底，而非完成真实视觉推理。
- `src/frontend/config/index.js` 指向 CloudBase 测试 API。正式运营前仍需绑定稳定的 HTTPS 域名，并在微信后台配置合法域名。
- 本轮代码已从 JSON 文件迁移到可配置关系型数据库层，并引入 local/COS 存储 adapter；默认配置仍是本地 SQLite 和上传目录，生产必须同时设置托管数据库和 COS。
- 飞书应用尚需创建/配置、权限申请、管理员审核、可用范围设置和双端真机验证；这些是仓库外动作，代码不能代替完成。

## 6. 验证口径

### 仓库中可直接确认

- 微信页面、交互处理、Flask 路由、AI 兜底、本地存储和 Dockerfile 均存在。
- 测试使用伪 AI、伪天气和开发登录，不覆盖真实模型、真实飞书、真实对象存储或平台审批。
- 本轮测试新增认证必需、两个开发账号隔离、飞书 OAuth v2、微信 jscode2session 和 AI 失败不得假成功场景。

### 历史记录声称已验证，但本轮仍需复验

- 7 项 pytest、Black、isort、flake8、前端 JavaScript 语法检查；
- CloudBase `/` 和 `/api/health` 曾返回 200；
- 微信开发者工具曾生成真机预览二维码。

### 本轮线上探测已确认

- CloudBase `/` 和 `/api/health` 当前返回 200，约 0.06–0.10 秒；
- CloudBase `/api/analyze` 可接收项目测试图片，但约 0.109 秒返回固定粉色裙子，确认 AI 静默兜底问题在线上存在。

### 本轮本地实现验证已确认

- 根目录 `.venv` 使用 Python 3.12，后端最终 `37 passed, 2 skipped`；覆盖认证、账号隔离、飞书/微信身份交换、AI 错误、COS 权限与生命周期、公共目录盘点/导入/可见性及部署验收工具；两项托管数据库集成用例因本机无服务跳过并由 GitHub Actions 执行；
- `src/feishu-web` 完成依赖安装，审计为 0 个已知漏洞，TypeScript + Vite 生产构建通过；
- 上述本地结果验证的是代码与模拟依赖，不替代真实飞书 JSSDK、真实 AI、CloudBase 新镜像和外部存储验收。

## 7. 当前判断

项目已从“微信小程序 Demo + 后端原型”推进到“微信端保留 + 飞书 H5/用户隔离 API 的本地 MVP”。下一发布门槛是把已经写入代码的认证和错误透明化部署到线上，并完成真实飞书、外部数据库/对象存储、隐私生命周期及双端验收。

当前最没有把握的是生产模型是否真正支持现有视觉请求格式；当前线上快速返回固定结果已经证明不能用 HTTP 200 作为 AI 成功证据。当前最大的遗漏风险是把本地缓存中的历史、收藏和衣橱误认为跨设备、跨实例的服务端能力。
